# Match the delivered claim to its actual lane

Input: the final affected criterion, source/dependency identity, available tools
and earlier observed results. Output: exact checks and outcomes, source-backed
findings and unresolved proof for the claimed host/operation/cohort.

Choose the smallest boundary that proves the criterion:

- Guidance/spec edits use installed frontmatter/reference/routing checks and the
  catalogue gate when available; no application install or build solely for prose.
- Authority/Store behavior uses focused `mix test` paths under
  `test/wotex_home/`, with real SQLite/Authority assertions for durable claims.
- Framed/peer behavior adds the actual local socket/TLS fixture; a pure codec or
  `--socket-free` run cannot qualify a socket/peer claim.
- Native packaging uses the affected [host workflow](../host-packaging/SKILL.md)
  and host guide. Window, assembly, installed identity and lifecycle need their
  respective evidence; no one artifact substitutes for the others.
- Physical dispatch/readback uses [local integrations](../local-integrations/SKILL.md)
  and the exact hardware cohort/lab procedure. Fixtures and firmware-host probes
  do not qualify a board, real effect or power-loss survival.

Read `mix.exs`, actual task source and the appropriate guide before execution.
[bin/test.exs](../../../bin/test.exs) uses already-built locked dependencies but
freshly compiles all Home into a temporary directory. It is a launcher fallback,
not a no-build test runner. `--socket-free` omits real sockets;
`--firmware-host` adds host probes without board qualification. Preserve those
limits rather than silently treating the fallback as an equivalent full lane.

For an operation/replay claim, use
[authority journey](../authority-journey/SKILL.md) before native shell assertions.
Inspect each criterion's public trigger, owner, forbidden effect and concrete
assertion. Record source/dirty tree, lock/producer pins, toolchain, host, schema,
artifact bytes and cohort as relevant. Earlier results remain reusable only
while their proving inputs/assertions and subject are unchanged. A newer sibling
checkout is not the consumed dependency.

On failure, capture the exact boundary and choose a discriminating probe across
input/review, current grant, transaction/history, transport, dependency or host
causes. Do not repeat a full build or resend an uncertain physical operation as
a diagnostic ritual. Remove only task-owned edits motivated solely by a rejected
hypothesis. Fix in-scope causes and rerun invalidated checks; missing prerequisites
remain unavailable, never successful evidence.

Before an authorized heavy lane, inspect available capacity and output ownership.
Track and clean only the run's newly owned artifacts. Preserve SQLite data,
retained histories/archives, shared deps/build caches and private custody. Apply
`mix format --check-formatted`, warning-free compile, affected tests and
`mix woh.spec.check` according to AGENTS.md when their surface/authority permits.
Report exclusions and exact results; no installs, host startup, physical dispatch,
release publication or production writes are granted by this workflow.
