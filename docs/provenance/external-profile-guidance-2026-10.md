## Implemented boundary

Authority forwards four closed reads to the single Store. Current profile
permission is required throughout; sources and targets also require enrollment
review. Context reconstructs the configured reader and reports only its basis
and availability. Source projection validates the configured owner's closed
catalogue and strips stable identities and their hashes. Target counters come
from validated retained history, including revoked identities, without requiring
a running source publisher or reader.

Artifact derivation resolves the exact actor-owned inspection, reconstructs its
manifest from owned immutable bytes and the matching current reader, compares
the retained inspection result, and releases each private byte lease. It creates
no source lease, original, policy generation or Store revision. Historical receipt
lookup remains independent of this fresh derivation. A dead custody process
returns `profile_custody_unavailable` rather than terminating Store.

The private Unix socket exports exact request fields and named result members.
CLI inputs use the existing descriptor/path custody checks with mode0600,
private0700 parent, no links, strict JSON and a4096-byte ceiling. These reads do
not enter the mutation-uncertainty allowlist or the retired-authority read list.

## Evidence limits

This establishes bounded software guidance through the local consumer. Dedicated
producer-unload and owner-timeout fault injection are not added by this slice;
their existing availability/timeout adapters remain dependencies. The tests do
not establish installed signed/paired interaction, native guided controls,
protocol-publisher truth, hardware identity, power-loss durability or physical
qualification. Guided construction and signed consumption remain subsequent
work. Physical dispatch remains disabled by default.
