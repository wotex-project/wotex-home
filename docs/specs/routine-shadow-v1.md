# Restricted routine archive shadow comparison

Version: 0.1.1. Updated: 2026-10-15. Accepted software comparison profile;
restricted archive comparison implemented; finite software evidence passes. Owner: WOH.20 H20-02/03/04/08/10.

This is read-only decision comparison before runtime extraction. It executes
Home's actual Rule/Compiler/Sandbox/RuntimeGate source and the public WoTEx
Compiler/Kernel from three exact supplied archives. It starts no Home service,
Store, transport, scheduler or device worker and selects no application
dependency or admitted successor profile. The fixture's installed mapping is
synthetic; its success cannot qualify a device, mapping, author or grant.

## Supported input and mapping

The first comparison scope is one closed Home v1 rule: explicit-request
trigger, literal-true predicate, Boolean `power` effect for one ordinary Light,
automation authority, block-unknown policy, ownership 1 ms, cooldown zero and
causal budget one. Other predicates/triggers/types/budgets/ownership reject
this comparison profile; they do not become an unconditional rule. Home's
existing source and receipt formats keep their meanings.

The harness supplies exact Home Rule/Event/Value values, desired-state map,
current gate decisions and elapsed time. The portable side supplies a WRO.01
installed Boolean writeproperty basis, reviewed fixture Thing/resource mapping,
offline registry, explicit WRO.02 Profile/Limits/Snapshot/Time and immutable
compiler archive identity. The fixture explicitly maps Home power to that
installed basis; it does not infer semantics from a matching operation/name.
The generic source has a manual trigger, literal-true root condition and one
absolute effect with the basis's exact completion/report contract. Rule ID and
source revision bind the converted source; target/value bind its context/input.

The portable host independently implements Home's narrow eligibility policy
before calling Kernel: matching explicit rule request, depth <1, whole-Thing
gate allow, this root not already consumed and desired state not already the
exact known requested Boolean. Unknown desired state permits an inert proposal;
it is not a reported match. Negating an unknown observed predicate is not used
to implement this policy. A suppressed request does not begin a generic run or
consume a root. Later release of a gate on the same original may therefore
produce its first proposal. The producer does not own Home desired-state policy.

After one eligible proposal, retain that original's generic Run and replay it
for duplicates; preserve Home's independent consumed-root accounting. Root
proposal spend in this sandbox comparison and held-effect spend in WRO.02 are
different observations. No synthetic held admission/handoff is manufactured to
make their counters equal. This first profile compares a single causal original
and independently initialized scenarios, not interleaving/restart or concurrent
different-original overlap. Wider durable composition remains inactive until
its owning journal/admission/guard evidence exists.

## Comparison and bounds

Compare ordered proposal cardinality, requested Boolean, exact mapped target,
whole-Thing domain, stable original/path and duplicate behavior. Home retains
its rule/root/depth/ownership labels; the generic proposal retains installed
basis/report threshold and has no grant. Hard constraints and operator override
precedence are supplied through Home RuntimeGate and independently checked by
the comparison host. Exercise both requested values, unknown/same/opposite
desired state, matching/unmatched/synthetic-ACK events, depth 0/1, safety allow/
deny/unknown, absent/live/expired/old-epoch leases, duplicates and blocked-root
release. Invalid/forged source/native state refuses. A mismatch fails an
assertion; a compile/load/selection error is a harness failure, not parity.

Each scenario uses at most one rule, one target, one causal original and eight
frames. At most 1024 independently initialized finite scenarios are selected;
source/profile limits still apply. The harness has no catch-up, compensation,
physical retries, runtime discovery or model-source input. Fixture compilation
and comparison do not replace the independently owned generic AST/mutation lane.

## Archive seam and acceptance

`elixir bin/check_routines_shadow.exs` takes explicit `--core-archive`,
`--continuum-archive` and `--routines-archive` files plus each corresponding
`--core-sha`, `--continuum-sha` and `--routines-sha` lowercase SHA-256 value.
Missing/extra arguments, nonexistent files or digest mismatch refuse before
executing archive code. Each Hex archive is at most 32 MiB; its decompressed
contents at most 16 MiB and 2048 members. Relative regular files/directories are
extracted into its own disposable directory; absolute/traversing/link members
refuse. The
consumer selects only those extracted producer dependencies with env=prod and
WOTEX_PATH_DEPS unset. A frozen explicit Home source closure is copied into the
consumer and freshly compiled, rather than using cached Home BEAMs. Its scope
must name every copied module and source digest. Nothing imports a sibling's
hidden API or copies consumer semantics into WoTEx.

Acceptance requires a passing finite parity corpus, unsupported/forged refusal,
fresh BEAM locations under the consumer build, passive producer application
metadata, and reproducible archive/lock/Home-source/fixture/toolchain identities.
Archive adoption and restricted software parity are distinct from production
dependency selection, activation, Store atomicity, native hosts and physical
qualification. Record actual commands/results before updating implementation
status; retained evidence belongs to its exact source/archive cohort.

Executed evidence is recorded in [the cohort record](../provenance/routines-shadow-2026-10.md). The decompression boundary follows [Erlang’s zlib contract](https://www.erlang.org/doc/apps/erts/zlib.html): bounded safeInflate output and inflateEnd completion checking. The recorded OTP lane was exercised directly.
