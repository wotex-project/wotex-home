# Native single-schedule panel v1

Version: 0.1.0. Accepted native composition, 2026-10-08. WOH.08 owns the
presentation and [original journal](native-pending-custody-v4.md); WOH.14/15
retain schedule admission, lifecycle, authorization and API semantics.

The existing Rules task offers explicit actions and schedules as separate views.
The schedule draft supports one-shot, daily, selected weekdays and UTC-anchored
fixed intervals for one enrolled ordinary Boolean Light-power action. It binds
the complete source/rule documents, a stable draft identifier/revision, actual
authenticated author and current target resource counter. Integer conversions
and all existing source bounds remain exact. Draft dates select calculation
labels or UTC bounds; they establish no qualified host clock.

Prepare reads original custody, authenticated identity and current granted
catalogue. Calendar preparation asks the existing host-owned timezone route for
the exact local label and installed-data digest. A one-shot gap cannot submit;
a fold requires an explicit valid UTC choice. A unique instant is displayed and
confirmed. Recurring gaps skip, recurring folds choose the first once. The
review shows target/action, retained timing, bounds, source version, late window,
clock tolerance and calendar consequences. No caller uploads timezone bytes,
clock trust or an execution proof.

Preparation is read-only. Recording screening, retaining admission, activation
and suspension each require their own reviewed confirmation and fresh operation.
Changed draft/choice clears confirmation; changed custody/controller refuses
publication. The shared coordinator repeats credential bytes, original native
reference and complete controller identity before publishing the complete v4
original. Publication precedes mutation. Uncertainty retains that original;
shared recovery uses its existing custody and exact lookup/retry. Startup and
view switching send no automatic mutation or recovery.

A successful or recovered admission provides a bounded hint to its retained
original, not an activation token. Activation preparation reopens that exact
original status under matching custody/context and displays its complete
retained schedule even if today's draft differs. A definite first refusal
cannot manufacture an admission hint. Every result checks complete original,
principal and closed receipt correspondence before durable removal. Failed
publication clears local confirmation and leaves the shared original available.

Readiness is an explicit current read, separate from immutable historical status.
An active schedule basis does not establish an autonomous running process or
device observation. The panel displays that runtime admission remains required.
The current Store refuses countdown admission; this panel exposes no fabricated
boot/clock/start input. Qualified controller time, autonomous runtime admission,
countdown delivery, composed active sets and physical dispatch remain separate
obligations. Default-disabled dispatch and existing Authority/Store ownership
remain unchanged.

The app shares one schedule model across windows. Busy/session/network/probe
guards include it; original resolution reaches it through the shared coordinator.
Session/access changes clear its review and current presentation while preserving
drafts and retained originals. Rule/schedule changes invalidate the other view's
current preparation. Narrow controls wrap through the established native layout.

Required evidence includes real Store interval and installed-calendar lifecycle,
independent gap/fold UTC choices, complete original publication and exact lookup,
changed draft/custody/controller, first refusal, failed publication and lost-reply
shared recovery, existing client workflows, source closure/typechecking and
rendered narrow/expanded views. Synthetic timezone content must fail activation
against a different actual installed root; a fixture cannot substitute current
host timezone custody. Signed installation, clock qualification and physical
execution require separate evidence.

`mix woh.native.schedule.panel.smoke` passed eleven actual private-Store
workflows: complete fixed-interval and installed `Etc/UTC` calendar lifecycle,
independent one-shot fold choices, recurring gap/weekday fold consequences,
synthetic/installed timezone refusal, lost reply with changed draft and exact
shared lookup, definite first refusal, publication failure/reload/retry and
changed custody/controller/draft guards. The proxy checks exact v4 publication,
authenticated source/resource joins and every immutable original lookup.
The interval draft reconstructs the independent cross-language SHA-256 golden;
conversion refusals cover leading-zero/expanded integers, multiplication overflow,
non-finite/negative dates, cadence bounds, invalid fold choices and empty weekdays.

Narrow activation/pending and expanded weekday views were rendered and inspected.
All scalar fields retain visible labels and accessibility labels after entry;
timing choices and session invalidation advance the draft revision and clear
confirmation. The complete app source typechecked with Swift 6 warnings as
errors. Existing shell edge/focus checks and fourteen native schedule recovery
workflows passed. Eighteen affected schedule API/macOS inventory/SPDX/dependency
tests passed in 8.4 seconds, with actual sockets/private files and no exclusion.

Locked formatting/compilation, owning contract/catalogue metadata, local
references and Git whitespace are required before the local commit. The app
assembly closure and macOS CI include the panel/check; remote CI, fresh artifact
assembly, signed installation, installed clock/host behavior and hardware effects
were not tested. Confirmed admission selection after app restart remains a
separate source-reload workflow; the current admission hint lives in app memory.
