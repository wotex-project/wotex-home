against the selected paired controller with current profile:manage. No selection
or file picker initiates signing, Keychain, controller RPC or mutation. Each
prepare/read/confirm is explicit. Targets and target access remain broker-local;

## Prepare and retain metadata

**PAU-01.** A paired preparation first obtains the actual selected session and
checks current profile:manage before any private file content is read. Its fixed
adapter requires explicit remote transport, exact association/key verifier and
current scope; no local capture, UDS fallback or imported key is permitted. Current
permissions/targets must equal the acquired scope, remain within approved grants,
and scope revision must not regress. Exchanges and private reads finish under that
same read session's deadline; late/cancelled results do not enter a view.

A human-review decision retains complete canonical original/payload, selected
association snapshot and selection generation, exact checked identity/revision,
association/scope metadata and applicable authoring basis. Paired decisions retain
no bearer, native local-capture record, Keychain access seal or reusable session.
Metadata may be tested with raw fixtures; it cannot construct a live production
session or sealed publication. Local decisions preserve their current behavior.

Keep original/payload private-file bounds: current-user single-link regular0600
file, symlink-free parent chain and stable descriptor/path/size witnesses. Import
payload is at most262144 bytes; smaller kind ceilings remain source/draft262144 and
fixture/envelope/profile/definition65536. Complete native original input ceilings
are4096 import,65536 candidate and262144 review, then canonical ceilings4096/32768/
131072. Source/fixture selection files and review input retain their exact closed
owning schemas,32 handles per category,256 citations and64 unresolved paths.

Data import and complete import freeze exact payload/summary and current controller
identity/revision under the profile API. Manual draft import and mapping use current
contract/grammar and basis. Complete candidate/review additionally check the current
contract and actual owned references; review uses an actual compatible manual
candidate receipt with current matching basis. Draft assessment verifies the selected
controller owns the exact draft/first revision and explicit source/fixture handles.
Read identity before/after contract/reference work and require stable revision,
principal/epoch and contract revision. Never synthesize remote-owned references from
a local file, fixture, capture or another principal's receipt.

## Fresh confirmation and typed result

**PAU-02.** Confirmation consumes the prepared decision only after acquiring a
fresh actual selected session. Require the original full selection snapshot and
generation, exact association/controller/creation/verifier, same principal/epoch,
unchanged grants and exact reviewed Store revision. Re-read applicable contract
basis and unchanged input correspondence; changed facts retire the decision and
require explicit reprepare, without editing its operation ID/revision. A read
session may have expired during human review; this fresh acquisition does not
renew that session or any operation/model budget.

Once confirmation acquisition begins, pending publication, fixed original runner,
typed receipt read, outcome publication and delivery share that one five-second
lifetime/seal. Remember and publish the exact v8 original before send. No session
reacquisition follows failure or possible send. A known initial server refusal
retains the paired original for explicit existing-only recovery/absence handling;
no caller supplies a successful result or clears memory on an unverified error.

A resolved manual authoring outcome includes its verified typed receipt in the
actual sealed publication. The fixed original-purpose session performs an
existing-only typed receipt read before pending removal, checks kind/epoch/ID,
expected revision+1 and full input/object SHA/size correspondence, then publishes
that matching outcome. Failure/late reply retains pending and uncertainty. No
mutable publisher or caller-provided receipt can initialize the sealed result.
After hopping to the presentation actor, repeat original lifetime and selection
checks. Failed delivery remembers the original and requires reload.

The actual import receipt establishes an owned draft reference for a later separate
assessment. Assessment yields its actual manual candidate receipt for separate
explicit source/fixture review. None becomes profile approval or control. No bearer
or completed signed session is retained in these successive human decisions.

## Presentation and invalidation

**PAU-03.** Show the selected paired controller and exact operation/revision/input
identity in review details. Existing explicit buttons, private file choices and
separate confirmations retain their behavior; do not insert automatic imports,
assessments or reads. Current-scope/authority/custody/transport/selection failure,
cancellation, wake or metadata replacement retires private results, owned draft,
input/grammar context and confirmations while retaining durable originals. Ordinary
invalid input retires only its prepared decision while current context remains valid.
Recovery always addresses the original association regardless of UI selection.
