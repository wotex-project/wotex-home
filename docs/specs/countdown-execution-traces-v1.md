# Independent bounded countdown execution traces v1

Version: 0.1.0. Software correspondence, 2026-10-08. WOH.04 owns temporal
admission, WOH.14 durable execution and WOH.16 recovery. This evidence extends
the [countdown lifecycle](schedule-countdown-lifecycle-v1.md) without changing
its writer, schema, public routes or temporal artifact scope.

The closed [68-trace corpus](../../test/fixtures/schedules/countdown_execution_trace_vectors.json)
is generated by an [independent Python event generator](../../test/fixtures/schedules/generate_countdown_execution_vectors.py)
that imports no Home code, live clock, bearer, transport or device. Each vector
has exactly an ID, duration, wall-confidence mode and at most 32 closed events.
Monotonic offsets bind the original due coordinate obtained from the source's
past start plus duration, rather than a Home planner result. The complete corpus
is bounded to 65,536 bytes. Thirty-three sequences run with each of qualified
and unavailable wall time; two further sequences execute the maximum 24-hour
duration. Live positive sources use one-minute and 24-hour durations. Exact
one-second arithmetic and window boundaries are checked separately by the pure
reference, not claimed as live one-second admission or host timing evidence.

The independent `Schedules.DurableModel` countdown mode accepts exactly five
integer attributes: start, duration, late window, initial watermark and original
clock generation. It uses signed-64 monotonic bounds independently of UTC limits,
checks the complete due-plus-late sum and keeps clock generation separate from
rule generation. UTC interval inputs cannot impersonate countdown observations.
The reference imports no planner, guard, Store, transport or credential code.
Its predictions create no admission or current clock confidence.

The actual Authority/Store harness first binds the source to an actual private
Store clock input. Its controlled software peer supplies either qualified UTC
or qualified continuous monotonic time with null UTC and unavailable wall time.
Forward fixture advancement changes only the Store's elapsed software timeline;
it cannot rewind that timeline, rewrite the admitted source, renew a queued
report or extend a deadline. A fresh synthetic report is accepted before queueing
after a large forward jump. Once queued, its exact revision remains sealed.
Published clock observations supply input time to the separate reference; its
watermark and dispositions are computed independently.

Every event checks actual read-only SQLite projections of activation, original
author/grant, rule and clock generation, historical missed cause, considered
watermark, disposition, causal spend and committed handoff. Complete immutable
consideration/effect rows are compared after every event. Each event also captures
a complete bounded SQLite image inside the fixture's private directory, with
private file mode. After the timed execution sequence, each captured image is
opened read-only and checked for its exact event revision and full snapshot
integrity. Copies create no Store or current authority and are removed with the
fixture. This checks every event's retained database without spending report
freshness on repeated independent validation between queue, claim and handoff. Original
receipt lookup uses the actual final author status at the end of each trace;
revoked authors cannot read private history. Two caller-exit sequences discard
an already committed internal Authority result, recover its original identity
through authenticated lookup and require no duplicate occurrence. This is
internal caller-result loss, not public socket reply loss.

Sequences cover acknowledgement and synthetic reported settlement, matching
no-send, cancellation without refund, early polling, half-open late expiry and
consumption without retry. Actual Store restart occurs at held, queued, claimed,
handed, protocol-accepted and observed phases. Clock unavailability is observed
before due and during each pending or handed phase. Return of original custody
cannot reactivate an expired source, even before due. Explicit clock withdrawal
retains its distinct changed-generation cause. Manual suspension can reactivate
the unchanged original source before due; due or expired sources refuse. Author
and target loss, restored grants, overrides and maintenance retain their ordinary
guard and generation semantics.

Five SQL fault sequences per wall mode fail occurrence, queue, claim, handoff or
clock-withdrawal publication. The previous revision, activation, phase, clock
generation and causal spend must remain exact while writes are disabled. A fresh
actual Store restart subsequently retains the old-boot missed barrier without
replaying tentative work or a committed handoff. Final-clock-loss savepoint and
startup-failure probes remain the separately documented lifecycle evidence.

The pure reference separately checks closed inputs, monotonic overflow, one-second
through 24-hour durations, exact due and exclusive late boundaries, all six
restart phases, same-generation return before due, exhaustion, failed withdrawal
and root conservation throughout every frozen sequence. A countdown has one
coordinate and no UTC missed-range summary.

Private software clock custody and LIFX qualification are synthetic. No physical
packet, actual target observation, storage power loss, installed sleep/clock
qualification, controller transfer, native countdown creation or autonomous
timer is established. Physical dispatch remains disabled. Source-bound autonomous
runtime admission, composed active sets and cursor compaction remain obligations.
