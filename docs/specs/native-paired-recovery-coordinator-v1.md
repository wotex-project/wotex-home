# Paired original recovery coordination v1

Version: 0.1.0. Owner: WOH.08 H08-09/H08-T9, WOH.14 H14-06/H14-T7, WOH.15 H15-07/H15-T8. Status: accepted coordinator/publication target; implementation and evidence pending.

Compose the [actual original-purpose consumer](native-paired-recovery-v1.md)
with the one process-wide pending coordinator. This adds no remote operation,
credential constructor, receipt identity or device qualification. Window/menu
selection and first paired capture remain separate successors.

## Explicit recovery and memory

Only an explicit action may reserve recovery. Require the exact paired entry,
permitted action, loaded journal, no busy/reload state and the shared sixteen
original limit. Reserve the existing coordinator busy state before any await;
loading or opening a menu still performs only private-file reads. Keep both
legacy local runner entries and local coordinator refusal of paired custody.

Remember the complete paired entry as metadata before possible publication or
send. This memory contains no bearer and joins existing local originals under
one capacity bound. Stored phases take precedence over remembered phases of
the same input/context/custody. After ambiguity, reload preserves remembered
originals even if a possible resolution publication removed their disk row.
Only an explicit recovery action may republish that same remembered original
under full current journal CAS; it creates no new ID/input or remote request.
The actual factory then checks the complete journal and retained association,
never the selected owner. No remembered metadata can construct a signed seal.

## Closed publication owner

The actual recovery consumer performs the fixed runner and publishes its
corresponding journal result. It accepts no caller-supplied successful outcome
or filesystem backend. Review cancellation first publishes the exact existing
token/digest intent, then consumes the same-lease continuation before sending.
Use only the fixed production pending file. Retained results change no row;
review results publish the exact decoded references; resolved results remove
only the exact original. Preserve every other row and retained v5 version.

Before publication check actual original app/association and full pending
custody. After the publication check the actual resulting snapshot and the same
original app/association. All work and delivery remain inside the original
five-second continuous lifetime; blocked file work cannot block cancellation
or prolong that deadline. Cancellation/expiry/conflict after possible
publication delivers no completion, sets reload-required and preserves memory.
Late filesystem completion may change disk but cannot clear memory or update UI.

Only actual verified runner delivery plus confirmed corresponding publication
constructs the private completion value. It exposes the resulting snapshot,
entry and closed outcome, with no bearer or session carrier in logs/reflection.
The coordinator consumes that value before clearing remembered originals,
calling shared resolution callbacks or presenting completion. Error, missing,
refused, unknown, stale or late results retain the original. No automatic lookup,
retry, renewal, approval, fallback or target-broker activity is added.

## Required evidence

Independent publication vectors cover retained, recovered review, exact
resolution, other-row preservation, stale/full-content/inode CAS and retained
v5. Exercise blocked/cancelled/expired publication ownership and late completion
without creating a signed session. Actual unsigned production coordinator
recovery must retain memory and disk before clock, SecItem or remote I/O; reload,
shared busy guards and the capacity bound remain effective. Existing local
coordinator/panel regressions pass. Actual installed signed success and
cancellation/publication/restart composition, macOS 15 TLS and physical/storage
qualification remain separate gates.
