## Outcome and dependency order

A selected paired controller with current profile:manage supports the same inert
manual import/assessment/review and explicit generation decisions as local Home.
The controller owns private source/draft custody, current policy/basis/CAS, model
workers and settlement. Native owns exact original preservation, actual signed
custody and explicit presentation. Schema/compatibility success, generated text,
source attribution, fixture evidence, profile approval, enrollment and physical
control remain distinct. This adds no physical dispatch or producer-specific API.

Required implemented foundations are [selected session](native-paired-session-v1.md),
[first capture](native-paired-capture-v1.md), [original-purpose recovery](native-paired-recovery-v1.md),
[sealed publication](native-paired-recovery-coordinator-v1.md) and
[typed domain transport](native-controller-domain-sdk-v1.md). Their actual app seal,
existing Keychain item, pinned TLS peer and host certificate-clock producer are
required; decoded public metadata/raw keys cannot create a production session.
New representation prerequisites are [v8 pending](native-pending-paired-authoring-v8.md)
and [v2 workspace](native-generation-workspace-v2.md), now implemented as private
metadata dependencies with [workspace evidence](../provenance/native-generation-workspace-v2-2026-10.md).
They create no signed session or dispatch. The paired manual closed consumer
now has transport/Store and actual unsigned-factory refusal evidence. Continue
with first paired generation submission/recovery, selected driver/panel composition
and installed signed acceptance. The existing-only workspace purpose now has
[executed transport/refusal checks](../provenance/native-paired-workspace-session-2026-10.md);
software checks do not establish successful signed publication.

## Current signed scope and human review

**NPA-01.** Refuse local-broker-only operations and unknown certificate clock;
remote unavailability stays selected, without local capture/fallback. Capture
selection snapshot/generation and use the actual selected factory: original app
seal first, existing account/association CAS, exact Keychain verifier and current
pinned TLS controller_scope. Require exact deployment/owner/epoch/principal,
revision at least association creation, sorted current permissions/targets as
subsets of original approved access, and current profile:manage. Public approved
grants alone authorize nothing. Targets are not inferred from profile permission.

All exchanges, private publication and delivery of one actual session share its
original five-second continuous lifetime, including scheduling/clock work; no
renewal or default remote/system clock. Recheck app/custody/association and actual
current scope at required exchange/publication/delivery boundaries. After possible
send, failed/late/cancelled checks retain uncertainty and originals.

Read configuration explicitly through typed SDKs in one selected operation.
Identity/contract/options/grammar revision and principal/epoch correspondence obey
their local owners; return only checked private input metadata plus original
selection/association/context/grant/basis identity. Do not retain a bearer, access
seal or reusable session in a human-review decision. Signing checks and metadata
comparisons are distinct; only actual factories create a live session.

Human confirmation may occur after that read session expires. At submission
acquire a new actual selected session, check its same original selection/generation/
association/controller/custody/principal/epoch, current grants, exact reviewed
revision/basis/contract/policy and unchanged input. This is fresh authorization,
not renewal of the expired read session or original/model budget. Changed facts
retire the decision; require explicit reprepare, never silently edit ID/revision.
After the submission acquisition begins, publication and request use only that
one lifetime/seal and cannot reacquire after failure.

## Manual originals and publication

**NPA-02.** Preserve all exact [manual input/file bounds](native-manual-draft-v1.md),
[complete authoring codec](native-authoring-originals-v1.md) and
[source/fixture review](native-authoring-review-preparation-v1.md) rules. Import
uses the chosen private file's exact framed payload; candidate uses actual owned
import receipt and selected source/fixture handles; review uses actual compatible
manual candidate receipt plus explicit attribution/evidence. No local source,
capture, draft path, source truth or fixture success substitutes for remote owned
objects. Check selected context/current profile scope before private payload I/O;
all private reads retain current-user/nonlinked/stable descriptor bounds.

Freeze complete original (and import payload) before confirmation. Remember the
exact paired entry, publish v8 pending via the actual selected-to-original capture,
then use its fixed closed original-purpose runner once. Paired capture requires
current profile:manage for these categories. Field/payload correspondence and
current Store guards repeat. Upload/chunk/status/cancel retain the existing typed
authoring protocol and finite owner lifetime; partial upload or timeout leaves
the original, never starts another operation or imports another file.

The paired TLS listener must supply a finite transient upload owner to its fixed
Authority. If none is supplied, create one bound to that same Store PID, retain
it for this listener lifetime and stop it when the listener stops. A supplied
owner must affirm that exact live Store PID before listening; pin its resolved
PID rather than following a replaced registered name. Monitor either owner and
fence listener/workers on its loss; never substitute a fresh owner mid-exchange.
The existing upload quotas, sixty-second maximum TTL and fresh process owner
epoch apply unchanged. Listener restart discards transient uploads and never
recreates them from durable receipts. Durable originals/receipts remain Store
history, and an explicit unchanged retry first reads that history. Sharing an
explicit owner with another adapter is allowed; the listener must not stop an
externally owned process. This lifecycle grants no principal permission.

On explicit retry first query exact original status; present checked history
resolves without replay. Missing may send that unchanged original once through
the owning protocol; lost final status retains it. A manual authoring result is
not approval/admission/control. Native target access stays broker-local.

## Generation, cancellation and manual review join

**NPA-03.** Preserve [first-decision](native-generation-ui-v1.md) and
[generation SDK](native-generation-sdk-v1.md) exact options, policy/range/example/
instruction/budget grammar and status correspondence. Choices and all budgets
start empty; model locality is relative to the selected controller. Installed
remote_export plus separate user consent is required for its remote model; paired
LAN transport alone cannot authorize that export. Preparation makes no model call.

The [generation original session](native-paired-generation-original-session-v1.md)
owns first capture and fixed original recovery, including workspace-required retry
versus existing-only reconciliation without a workspace prerequisite.
After fresh signed submission checks, publish complete v2 workspace root/attempt,
then v8 pending, then transfer the same selected lease to a fixed generation
original-purpose runner. No workspace-only send, provider fallback, automatic
attempt, deadline renewal or identity substitution. The files have ordered CAS,
not a multi-file transaction. Interrupted publication explicitly restores the
same bytes to pending under actual existing original custody.

The [workspace session contract](native-paired-generation-workspace-session-v1.md)
defines the distinct existing-only workspace purpose in the actual signed factory.
It fixes one exact workspace entry, workspace/association snapshots and closed
action: status, cancellation, pending restoration, draft assessment or separately
confirmed archival. It exposes
no arbitrary SDK callback or caller-supplied successful signing backend. Validate
the retained association/controller/creation/verifier/context and current scope
before accessing private material, around every exchange and at final publication.
For cancellation, continue only the exact false-to-true intent CAS successor under
the same original lease/seal before sending. Matching cancellation can continue
to the exact true-to-false successor; neither continuation reacquires custody.
Status makes no write. Restoration checks existing-only root/latest status and
publishes only the exact retained original, refusing cancellation intent or another
pending operation. Possible file completion after expiry retains memory and
requires reload; it cannot deliver a live consumer.

Read root/latest attempt by retained identity. Repair requires the matching
invalid predecessor, checked owned raw draft/report and explicit feedback consent;
running/unknown/compatible/missing/expired/retired/budget exhaustion refuses.
Cancellation confirms the persisted root, publishes local intent before its
idempotent SDK request and clears intent only on checked cancelled status. Use
actual existing original association/custody, not another selection; no expired
session can send or publish a cleared intent. Lost reply retains intent and claims
no stopped remote model.

An explicit generated-draft assessment obtains exact owned draft bytes and stable
generated import receipt from that controller, checks result metadata/SHA, then
builds a fresh manual candidate under current contract/reader/basis/CAS and the
deduplicated explicit root sources/fixtures. Publish through the paired manual
boundary above and use its actual receipt for ordinary attribution/review. Never
cast a generation attempt into a manual candidate reference.
New attempt/manual-assessment decisions require the selected association to match
that workspace's original controller and principal. Another selected controller
may not receive its instruction, draft or references. Original status/cancellation/
recovery still use their fixed original purpose irrespective of selection.

## Recovery and presentation

**NPA-04.** Recovery is fixed to the entry's original association and action,
regardless of current UI selection. Actual existing-only factory repeats signed
app, association/pending full CAS, exact controller/principal/verifier/creation
and current scope; no local/manual key can substitute. Only actual verified
runner delivery plus sealed corresponding publication may clear remembered state
or deliver a callback. Mixed v5–v8 versions retain their actual version.

Generation lookup/retry keeps running and null-result unknown pending. Separate
confirmed acknowledgeUnknown and acknowledgeAbsent use existing-only status and
actual signed publication: unknown/null may clear only with its own confirmation;
not_found may clear only after accepted uncertainty. Running, wrong scope/custody,
malformed/refused/late responses or stale CAS retain originals. A now-present
settled/cancelled/preparation row resolves with its actual outcome. Neither action
sends mutation/export, refunds budget, stops a model or archives workspace.

Opening/loading/editing/selection/startup has no signing, Keychain, configuration
RPC or model action. Each action is explicit. Invalid selection/scope/authority/
custody/transport retires private displays/input/decisions/confirmation, retaining
durable originals. Explicit workspace archive requires reconciled pending and
cancellation intent, current matching status and separate uncertainty confirmation
when missing/unknown; running always refuses. It deletes only client metadata.
