## View and fresh action

Only an actual selected production session can derive the paired power view
basis. Retain public association snapshot, authenticated scope, scoped Thing rows
and presentation generation; never retain a bearer, custody seal or session in
presentation. Its private constructor has no raw-key/scope/fixture initializer.
Carry the original continuous deadline as timing metadata solely for final read
delivery. Check that deadline after projection work and before the presentation
actor publishes the view. This metadata does not renew the original session.

On/Off is available only for an exact current-view writable Light row with read
and ordinary control permission and the target in that authenticated scope.
Saved association grants never enable it. The view is historical after delivery;
every click acquires a new actual selected session and checks complete snapshot
and presentation generation plus deployment/owner/principal/epoch, revision
floor, unchanged permission/target lists and the exact retained Thing row.
Scope drift clears presentation before another decision. No cached view grants
later authority. Do not substitute a local credential or socket after refusal.

Create one operation ID for the click and derive its existing closed power input
from the exact row/revision/value. Authority/Store remain responsible for current
permissions, target/declaration/profile/revision policy and immutable receipt
identity. Fresh scope cannot replace the original request once capture begins.

## One submission reservation

The shared pending coordinator reserves busy state across candidate derivation,
remembering metadata, fixed-file first capture, the fixed first retry meaning,
receipt publication and actor consumption. Preserve all other originals and the
sixteen-entry bound. Do not release busy state between capture and submission.
No caller supplies a successful outcome, runner, publisher or alternate custody
backend. These operations share the original selected session's five-second
lease; no step reacquires or extends it. Retain the exact original before any
possible request and clear memory only after the closed receipt and matching
journal publication are confirmed within that lease.

Window and menu use the same sender/journal. Check actual publication delivery
again at driver and presentation boundaries. If a higher hop becomes cancelled,
expired or changed after an earlier valid consumption, remember the exact closed
publication's original metadata again and require reload. This conservative
memory step sends no request, writes no file, imports no key and conveys no
authority. Later explicit recovery performs its existing exact-original guards.
An unconfirmed result must never be reported as proof that nothing was sent.

Receipts remain staging evidence: held, queued, protocol acceptance and observed
state stay distinct. Stored reports are not changed optimistically. Only a
confirmed resolved publication may trigger a fresh stored-report read, whose
new session cannot repair or renew the original operation. Missing clock,
unsigned app, failed custody, scope drift, cancellation, expiry and unknown
publication preserve refusal/uncertainty and never enable physical dispatch.

## Development evidence and delivery obligations

Independent metadata vectors must cover control/read/target refusal, identity,
epoch/revision and scope-list drift, changed role/profile/resource revision and
read-only rows. These comparisons create neither a view basis nor a signed
session. Keep actual unsigned factory refusal, private first-capture/late
publication/original recovery tests, real Authority/TLS/SQLite original receipts,
and local window/menu regressions. Historical control grants must fail to stage
through the production shared model without an authenticated view basis.
