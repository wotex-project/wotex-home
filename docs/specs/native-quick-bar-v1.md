# Native quick bar v1

Version: 0.1.0. Implemented menu-bar composition with bounded software evidence,
2026-10-08. WOH.08 owns this presentation. It adds no Authority route, credential,
control permission, worker or physical qualification.

The app installs a SwiftUI menu-bar extra with a window-style dropdown. Its
house icon changes to an attention icon when the shared journal has an
unresolved original/error or authenticated health reports unknown outcomes.
The dropdown shows the selected session, authenticated controller availability,
physical-dispatch enabled/disabled state at the last explicit read and scoped
Things. Opening the app/dropdown only loads the private journal. It never opens
credential custody, queries the API, probes a device or resends a request.
Explicit Refresh reads existing health, catalogue, snapshot and overrides.

Each exactly declared ordinary writable Light exposes On and Off buttons.
They call the existing typed ordinary power path with the displayed resource
revision and refreshed authority epoch. The current row must still belong to
the read scope with the same identity/declaration/revision, and the app-wide
busy, session and journal guards must permit starting work. The Store repeats
current authentication, grant, declaration and policy checks. A read-only Thing
has no power controls. A stale/invented row cannot create an operation even if
a delayed visual event bypasses its disabled button.

Stored power is labelled Stored and retains reported quality and trust. No
snapshot value is promoted to current/fresh state; it can be stale or synthetic.
A request never optimistically edits the report. Last power request shows its
original authority and durable receipt or unresolved status separately. Held
and queued requests are not device results. The default physical-dispatch gate
remains disabled. Full provenance/freshness inspection belongs to the Things
task in the main window.

One `HomeApplicationModel` owns the existing shared models and pending journal.
It binds original resolution, session/access changes and busy guards before
constructing any window. Windows and the dropdown consume those same instances;
closing a window cannot remove the guards or recovery callbacks. All journal-
using models receive that exact coordinator. Host sleep/wake invalidates scoped
read presentation, and an already-running health refresh cannot republish its
old generation after invalidation. No timer automatically refreshes reports.

Successful explicit credential import releases its busy guard before session
invalidation and the follow-up read. A failed save keeps the input and returns
the UI to an available state; it supplies no fallback credential.

The dropdown mounts the same original recovery panel, with controls that wrap
at its 380-point width. Original lookup/retry uses existing-only custody and
fixed original-operation delivery. A lost reply or unexpected/internal power
server error retains the original. Only a closed first-attempt refusal or a
verified result permits removing it. After shared reconciliation, the receipt
area marks the original reconciled and allows explicit receipt lookup; it
never infers an observed power value. Missing results remain retained.

Open Home brings up the named main window. Quit UI terminates the client;
controller enable/stop remain explicit Setup actions. UI lifetime and an enabled
background controller are independent. Closing the dropdown changes no session,
draft, pending original or controller setting.

`mix woh.native.quick.bar.smoke` compiles the production model/dropdown closure
in Swift 6 for arm64 macOS 15 and checks fifteen actual private-Store workflows:
On/Off staging, lost-reply lookup/retry in a fresh native process, an internal
error after commit, failed journal publication followed by exact recovery,
changed custody, read-only/empty scope, another model's in-flight inspection,
a retained rule original, sleep/wake during a read, definite first refusal and successful/failed explicit
credential import with an injected saver.
The proxy verifies complete journal input/context/custody before every power
mutation. Exact retries keep the original request bytes. Store revisions,
held/queued/claimed/unknown counters, principal-private receipts and unchanged
synthetic stored Off reports are checked. Mounted 380-point light/dark previews
include startup, power receipts and retained power/rule originals. Fixtures
open no Keychain, install no service and send no device effect.

The complete app entry point and menu-bar scene are checked separately by native
app source compilation/assembly. Fixture compilation and mounted dropdowns do
not establish actual system menu-bar accessibility, signed installed custody,
SMAppService lifetime or physical qualification. Those installed-host and
hardware obligations remain open under WOH.08 and its host/lab procedures.
