This consumes the exact [v5 original](native-pending-custody-v5.md) through

## Original purpose and custody

An explicit factory consumes an original entry, action and complete current
pending/association snapshots. The entry must be present exactly in the journal,
including its phase; validate the complete closed codec and action. Select the
association by the journal's immutable association ID, irrespective of the
current local/remote selection. Require the complete controller, creation and
credential-verifier join, exact deployment/owner/epoch/paired principal and
unchanged input. Edited label/endpoint may preserve that immutable join. No
association, changed binding, incompatible action or malformed input refuses
before credential/network work. Pure correspondence is never a session seal.

Use the selected factory's actual signed protected-app gate, original existing
SecItem, pinned TLS and authenticated current scope machinery. Repeat the exact
authority/principal, revision floor and approved-grant subset checks. Only this
actual entry constructs an original-purpose session; there is no raw key,
decoded scope, injected successful backend or fixture-directory constructor.
The original purpose retains one entry, action and both complete snapshots.
It has no generic SDK operation, new operation-ID, approval-renewal or target
broker interface, and cannot be used as a selected mutation session.

Acquire and use one original five-second continuous lifetime. Never reread or
reseal a cached credential to renew it. At opening, actual verified pre-send,
validated response and typed delivery, repeat both fixed-account no-op full
descriptor/content/inode CAS checks and actual original app/credential checks.
Missing/unsafe/changed files, selection or metadata invalidate the in-flight
original even when its binding ID remains equal. Snapshot checks create no
absent account directory, change no journal bytes/version/revision and start
no lookup or fallback. The bounded domain owner includes blocked clock/SDK
work before I/O and final delivery in that same lifetime.

## Closed runner and cancellation intent

Keep both local runner entries and the local coordinator's paired refusal.
A separate paired entry requires explicit operation-local remote transport,
the original association/context/verifier and canonical input/action. It shares
only the existing closed ordinary SDK switch. It always refuses native target
brokerage before I/O. Forward exact original fields, operation ID, epoch,
principal, expected revisions, profile bytes and original review references;
never create a new input or approval. Successful receipt principal fields must
match the original principal before typed receipt delivery. Existing typed
rule/schedule/override/maintenance/profile correspondence remains required.
Missing/refused results retain originals; transport or validation ambiguity
remains unknown. There is no automatic retry, UDS call or credential fallback.

An explicit cancellation of a retained profile review must publish the same
token/digest as `cancelPending` before sending cancellation. The caller first
holds actual original-purpose custody. A continuation may consume only the
actual newly published journal snapshot: exactly one revision advancement,
the same entries except that original's permitted review-to-cancel transition,
unchanged v5 version and exact retained input/context/custody. Verify the fixed
current file plus original app/association custody before returning the
continued private session. Preserve the original access and deadline; this
continuation makes no new credential or scope acquisition. Cancellation/expiry
after a possible private publication requires reload and permits no API send.
A review-phase cancellation session cannot run its cancellation until this
publication is confirmed; lookup remains an independent explicit action.

The consumer exposes only its bound entry/action, public association/current
scope and closed recovery outcome. Its bearer, purpose state and sealed
continuation have no serialized/debug/reflection/log carrier. A current-check
entry may repeat original custody before a coordinator publication; it returns
no credential or authority token. Actual journal phase/resolution and shared
window/menu composition must retain before/after custody and full original CAS,
and clear memory only after confirmed matching receipt and publication. Those
coordinator and first remote-capture joins remain separate successors.

## Required evidence

Independent original/association/action vectors must show that local or another
remote selection still chooses the original association. Include substituted
controller, generation, verifier, context, input, phase and missing original;
native-access exclusion; exact cancellation continuation and rejected altered
tokens/input/other rows/version/revision. Actual private files must check
unchanged bytes, stale/inode/full-content CAS, capacity and fresh-process checks.
No fixture may manufacture a production signed session.

The actual unsigned production original factory must refuse before the fixed
account inspection, SecItem, clock or network. Exercise the closed ordinary
runner over real Authority pairing/SQLite/pinned TLS: original lookup, exact
retry without a new revision/effect, missing receipt, refused scope and restart
recovery, with unchanged local paired refusal. Raw-key foreground transport
fixtures establish that adapter only. Independent wrong-principal replies and
late/cancelled delivery must retain the original. Actual installed signed
Keychain/session/continuation success, macOS 15 interoperability and physical
or storage power-loss qualification remain separate gates.
