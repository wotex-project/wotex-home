## Inputs, bounds and current scope

**NPE-01.** Keep the five guided drafts and complete-original input bounds:
inspection/trust/target are at most 16,384/4,096/32,768 decoded UTF-8 bytes;
operation and target/source IDs are 1–128 ASCII bytes, digests lower hex64,

in operator order. The owning codecs reject unknown/duplicate fields, coercion,
noncanonical bytes, bad object closure and overflow. Guided validation is pure
before signing. Complete files retain the existing nonlinked same-user 0600
single-link descriptor/name/size checks and are read only after live paired scope.

Capture the original selected association snapshot/generation. An actual selected
factory checks signed app access before private account/Keychain work, obtains the

exact deployment/owner/epoch/principal, current revision at least association
creation, sorted current access contained in the originally approved access and
current profile:manage. Target status/basis, source choices and target decisions
additionally require current enroll:review. Approved historical access alone
cannot satisfy either requirement. No local capture, socket or credential fallback.

The finite paired transport checks current scope before and after every closed
SDK exchange, including identity and status. Preserve the same permission/target
sets within the action, exact context and association, and a nonregressing Store
revision. Existing app/Keychain/association checks remain around opening, actual
verified pre-send, decoded reply, publication and delivery. Additional prepared
lifetime checks can only refuse; they cannot replace a signing check or renew time.

Caller-supplied outcomes/receipts or public metadata cannot clear production memory.

## Original association recovery

**NPE-05.** For paired external pending entries, enable exactly lookup, retry and
separately confirmed acknowledgeAbsent. cancelReview/acknowledgeUnknown refuse
before signing, clock, private publication or transport. Ordinary local runners
continue to refuse paired custody. Existing-only recovery uses the entry's original
association/controller/creation/verifier/context and full pending/association CAS;
it does not read a decision file, rebuild from guided fields or need current UI
selection. Current profile:manage and, for target kind, enroll:review remain required.

Lookup is status-only. Retry first reads exact history; only missing permits the
unchanged original once, and only its current authority epoch permits mutation.
A historical epoch can still be looked up under the owning authorization rules.
Known verified history resolves with its actual typed receipt. Missing lookup
retains. AcknowledgeAbsent uses status only: missing resolves local metadata only
with the UI's separate uncertainty confirmation; present history resolves its real
outcome. It does not cancel, rollback, revoke, stop a source or infer physical state.
Lost/invalid/refused/late replies, stale file CAS, revoked scope and unavailable
custody retain the original. Process restart reloads exact canonical v9 bytes.
No automatic retry or resolution follows loading.
