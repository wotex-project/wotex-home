## Selection and passive loading

The process-wide application model owns one driver for windows and the menu.
Construction binds guards without filesystem, credential, API or device work.
Initial surface loading reads private association and pending metadata only.
An absent safe association document has its existing in-memory empty/local
meaning. Unsafe or malformed custody remains unavailable; it never becomes that
default. Saved access is historical and cannot authorize a control button.

Controller selection is explicit and uses the complete original association
snapshot CAS. Changes obey the shared busy/original guards. A no-op still checks
the original inode/content/revision. Selection or reload invalidates scoped
presentation before any possible publication; uncertain publication retains the
selection original and requires reload. Loading or selecting a row never opens
Keychain custody, performs a lookup or launches an execution owner.

## Requests and original recovery

Explicit selected Home and Thing reads use the shared asynchronous driver.
Local reads use existing local custody and UDS. Paired reads require the actual
selected factory and its original absolute lease; never cache a bearer or seal
in presentation. Check authenticated identity/principal/epoch around composed
reads and validate the full selection snapshot before delivering presentation.
Preserve stored-read/device-probe distinctions and continuous freshness guards.
Changing any row, selection, inode or generation invalidates the old completion.

Production local credential acquisition and local SDK requests also use a
separate metadata fence. Check the loaded local snapshot before custody, before
the request and after completion. An unavailable/remote selection refuses before
local custody or UDS; no failed paired operation installs a local transport.
The remote TaskLocal transport remains distinct from this local fence so a
local guard can never satisfy the paired runner's remote-only requirement.

Explicit local original recovery continues through the journal's closed
original validator and existing original custody. That fixed runner uses its
original local context, independently of the UI's newly selected controller.
This local recovery scope is not a signed seal or a paired transport. Paired
original recovery uses its recorded association through the actual production
coordinator, independently of UI selection; the window and menu share the same
journal and callback. No recovered operation/input/owner is substituted.

A paired operation requires an explicit trusted certificate-clock producer.
Missing confidence is visible unavailability with the selected controller
retained. Do not derive zero-uncertainty confidence from `Date`, decoded scope,
saved permissions or a foreground fixture. Local-only tools remain fenced until
their own async paired successors are implemented; no generic credential-loader
or socket-path substitution turns them into remote tools.

## Required evidence and remaining delivery

passive loading, disabled selection, stale/no-op/away-and-back changes,
malformed custody and no local fallback. Exercise the production shared model
and typed local reads against a private real Store, then the closed local
original after an external selection change. Preserve existing menu/Thing and
local/paired journal regressions. A directory fixture, raw foreground key,
metadata fence or async read callback cannot create a signed paired session.

Paired first-power composition now follows the
[paired power contract](native-paired-power-v1.md). Actual signed paired
reads/submission/recovery, the owning certificate clock, paired receipt history
and remaining paired tool composition are unfinished delivery obligations.
Installed macOS 15 TLS and lifecycle, real Keychain custody and hardware/storage
qualification still need their actual hosts. These software checks do not
enable physical dispatch or qualify a device.

## Development implementation and evidence

The shared application model now owns the production driver and both Controller
pickers. Home/Thing reads use fresh selected sessions through their async reader
boundary; paired delivery repeats bounded original custody and the same lease
before the actor publishes presentation. Remote read results expose no bearer.
Local credential capture and SDK requests use the distinct metadata fence.
Paired journal callbacks are wired to the actual original coordinator and remain
disabled without the explicit trusted certificate clock. Remaining local-only
tools are fenced. Paired first-power controls now share the production selected
session and closed journal submission owner; installed signed success remains
an independent obligation.

The new private-Store driver task passes actual scoped Home/Thing reads, passive
startup, generation invalidation, stale/no-op/away-and-back CAS, malformed
metadata, remote no-local-capture/probe fallback and exact local original retry
after an external selection change. The production dropdown is mounted and
rendered at 380 points. Existing menu workflows, selected-session/owner-deadline
and unsigned refusal, local journal publication/restart, and paired first-capture,
bounded publication, real pairing/TLS/SQLite originals/restart/revocation and
wrong-principal regressions also pass. These use Swift 6 warnings as errors on
development macOS 27 targeting macOS 15; foreground raw keys and private
directories establish adapter/metadata behavior, never installed paired custody.

Final presentation uses an explicit unavailable picker value and human-readable
metadata refusals. A request detecting changed metadata exposes reload-required
and clears scoped presentation. An in-process generation nonce also invalidates
an earlier local completion after an unchanged metadata reload. Formatting,
warnings-as-errors compilation, full app typechecking, twenty contract/catalogue
checks and five affected macOS packaging tests pass.
