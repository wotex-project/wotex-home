## Scope and inputs

This owns the fixed original-purpose consumer for paired generation preparation
and attempt originals. [Composition](native-paired-authoring-generation-v1.md)
owns human choices, fresh selected authorization and presentation. [v8 pending](native-pending-paired-authoring-v8.md)
and [v2 workspace](native-generation-workspace-v2.md) own complete exact metadata
and private CAS. The [workspace session](native-paired-generation-workspace-session-v1.md)
owns existing-only status/cancellation/restoration/assessment/archival.
No codec, Store schema, provider API or sibling semantic contract changes here.

An original entry is pending phase, category generation, with its complete canonical
preparation or attempt document and exact deployment/owner/epoch/principal and
paired association/controller/creation/verifier custody. The owning codecs bound
preparation to32768 UTF-8 bytes and attempt to2048, with positive S64 epoch and
expected revision at least association creation. Metadata contains no credential
or live seal. Unknown/malformed values refuse without repair or new identity.

Actions are lookup, retry, acknowledgeAbsent, and acknowledgeUnknown for attempts
only. cancelReview and acknowledgeUnknown for a preparation refuse before signing,
clock or transport. Every action requires original association/context/verifier
correspondence, originally approved and current authenticated profile:manage.
Current targets/permissions remain subsets of original access and unchanged within
one action. Ordinary local runners still reject paired originals.

## Workspace before any possible mutation

**PGO-01.** First submission uses an actual fresh selected signed session. Publish
its complete root or exact attempt append in v2 workspace before v8 pending and
before any generation mutation. The caller remembers the pending original before
possible pending publication. The general paired capture entry must refuse a
generation entry unless given its explicit matching workspace witness.

The workspace snapshot must contain exactly one checked entry with the same
context and custody, no cancellation intent, and the submitted original exactly
its latest attempt or, when there are no attempts, its preparation. This matches
complete canonical bytes, not only operation ID/SHA. Enforce full workspace,
association and pending file witnesses around publication and every exchange.
The private original purpose retains this workspace witness while publishing its
matching pending outcome. Status or outcome cannot change workspace contents.
No workspace-only send, callback-provided result, selected-custody fallback,
operation rewrite, automatic repair or new deadline is allowed.

Explicit retry may send a missing original, so it requires that same matching
workspace witness and no intent. A different latest attempt, context, custody,
corrupt/missing workspace or concurrent workspace change refuses before mutation.
A known settled/running/unknown row is read first and is never resubmitted.

**PGO-02.** Lookup and separately confirmed acknowledgements are existing-only and
may reconcile a complete pending original without a workspace file. A damaged or
removed client workspace must not force blind replay or prevent reading durable
history. These actions fix pending/association witnesses and never publish, repair,
load as a prerequisite, or mutate a workspace. Retry remains unavailable until the
proper workspace is explicitly restored. This distinction cannot authorize a
missing preparation/attempt by renaming an existing-only action.

All actual factories first check real signed app access, then existing Keychain
custody and current pinned TLS scope; public metadata/raw keys cannot create a
session. One original five-second continuous lifetime covers acquisition, ordered
publication, SDK/status and final sealed result delivery. Scope revisions never
regress within that lease or its exact pending-removal continuation. No acquisition
or renewal runs after possible send/failure. Failed/late/cancelled checks retain
uncertainty and the exact original; late private completion requires reload.

## Closed outcomes

**PGO-03.** Use the owning generation SDK's status-first delivery. For retry only,
missing status may send that unchanged original once, then read status; a lost reply
retains the original. Preparation lookup resolves a checked actual prepared,
cancelled or retired result. Attempt running/null and unknown/null retain pending.
Known settled/cancelled history resolves with its actual outcome. Native does not
infer source review, approval, admission, stopped model or unspent budget.

acknowledgeUnknown uses status only and may clear unknown/null only with its own
explicit confirmation. Missing retains; running retains. acknowledgeAbsent uses
status only and may clear not_found only with separate explicit acceptance that a
request/result may still arrive. Present unknown/null or running retains; present
settled/preparation history resolves with its real outcome. Neither action sends
mutation/export, refunds a budget, cancels a model or archives workspace metadata.

Only the actual fixed runner plus signed corresponding pending publication can
remove production memory or deliver a callback. Retain actual v8 version, exact
original identity and every other row. The generation namespace and full other
controller/principal isolation remain unchanged across native/Store restart.
