## Scope and prerequisites

Adopting the [civil calculation join](routine-civil-calculation-v1.md) changes
code that can determine a schedule's original UTC coordinate. A Home-only
compiled digest cannot bind changed producer implementations. This contract
owns the fixed complete temporal cohort, v4 correspondence and current Store
integration. It does not enlarge single-schedule admission, qualify clocks,
change source/receipt schemas or enable physical dispatch.

Before selection, execute the Home civil archive cases against one inspected
ExBooking SP.09 CIV-06 and WoTEx WRO03-09 source cohort. Select exact immutable
Git revisions or published versions in mix.exs/mix.lock, including core,
Continuum and Routines. Keep existing protocol/profile pins unless coherence
requires an explicit reviewed change. Local archive execution does not prove
remote availability or publication. No branch, tag, release or push is created.
Release legal/native inventory changes follow their host packaging owner.

## Complete runtime identity

**RTR-01 — Fixed bounded closure.** The temporal digest inventories these ten
trusted applications in exactly this order:

`[:wotex_home, :wotex_routines, :wotex_continuum, :wotex, :ex_booking, :decimal, :jason, :ex_json_schema, :nimble_options, :tz]`.

This covers the selected temporal producer code and its non-OTP runtime
dependency closure, including core JSON/schema/numeric helpers. Optional
Profiles/ExMaude APIs are not called by this calculation. Host/native/ERTS/Elixir
qualification remains separately required; this manifest is not hostile-VM
attestation or atomic live-upgrade protection. Adding another semantic dependency
requires revising this closure before it enters the calculation path.

Each application binds its declared version, complete unique module list and
complete retained BEAM SHA-256s, with loaded/file consistency and old-code
refusal under RuntimeArtifacts. Missing/empty/malformed metadata, unavailable
files, oversized artifacts or any inconsistent member refuse the whole cohort.
No absent optional producer is dropped from a current temporal proof. The digest
domain is exactly `wotex-home.single-schedule-runtime.v2`, retaining the existing
deterministic term encoding of `{domain, manifest}`. Application order is part
of identity. A name/version, source pin, lockfile hash or producer's declared
producer_basis alone cannot replace this complete current inventory.

**RTR-02 — Reader and guard bounds.** RuntimeArtifacts permits at most eleven
trusted applications per request, 1024 modules each and 16777216 bytes per
artifact. The parsed checksum memo is bounded to 11264 modules. This successor
supersedes the former 512-module cap for every trusted inventory scope: the
actual Home application already declares 541 modules. Inventory must retain
all of them, including tooling modules; filtering or truncating the declared
module list to fit the old cap is forbidden. Existing 256 code
paths, 16384 directory entries, four temporary readers, 65536-byte reads and
five-second reader timeout remain. Preserve complete EOF/read/digest checks,
old-code tests, current path checks, reader cleanup and sequential OTP fallback.
Existing manifest/domain outputs for smaller requests keep their encoding.

The Store guard inventory is RTR-01's ordered ten applications followed by
wotex_udp, a union of eleven distinct applications. It opens with a fresh
complete inventory and closes with another exact equal inventory. Subset
requests preserve their caller's order. Unselected requests use independent
readers. No inventory survives the invocation or seeds a retained receipt.
The scope closes before the existing final unscoped execution guards, which
read current artifacts again. Failed opening/closing inventories cannot publish
a positive poll slot, occurrence, queue, claim or handoff. The existing
[withdrawal/rollback contract](runtime-guard-inventory-v1.md) retains original
committed phases, spend and uncertainty; an observed failure cannot be undone
by restoring a file during the same invocation.

Qualification retains the existing finite window, cursor, countdown, guard

Process-local positive reuse requires the same complete fresh runtime/source
binding; historical basis bytes cannot seed it. Failed/changed bindings clear it.

**RTR-04 — Historical compatibility.** v1/v2/v3 bases remain decodable under
their exact old obligation lists and hashes. They are historical evidence only
and cannot equal a current v4 artifact. Never rewrite, upgrade or synthesize
proof/authorization from a retained row. Re-admission requires the actual
current original author, review inputs and normal revision/generation barriers.
An old active generation must fail current admission and follow existing
withdrawal, retaining all immutable receipts, original IDs, no-repeat watermarks,
committed root spend and uncertain handoffs. Same-owner restart repeats current
basis checks; copied/restored data remains quarantined. Schema/table and backup
formats stay unchanged for this successor.

## Current authority boundaries

**RTR-05 — Repeat at the writer.** Authority may calculate outside the writer,
but the single Store owns every current admission and transition. At admission,
activation/poll/occurrence preparation, queue, claim and final handoff, repeat the
actual current source/rule/generation, complete active set, original author's
epoch and permission/target grant, exact declaration/resource revision, portable
profile/trust/custody, invariant/override, clock/window, capacity, serialization
and no-repeat/causal accounting required by the owning operation. The v4 runtime
binding is an additional current fact. It cannot cache or replace any mutable
fact, clock reading, hardware qualification or effect decision.

The final handoff checks current qualified clock confidence wholly inside the
half-open occurrence window after code inventory work. No deadline or report
freshness bound is widened to make a slower path pass. A stale source/runtime
refuses or withdraws under its owning phase; it cannot queue catch-up work.
Lost replies recover the scoped original; no generic projection generation
creates a new original. A `stale_schedule_admission` returned by the final
unscoped queue/no-send/claim/handoff guard is a current-basis policy denial:
restore tentative work, retain any required sticky withdrawal against the
original phase and return the typed refusal while leaving the writer usable.
It is not database corruption. Raw SQL failures, damaged historical content
and other unclassified errors still roll back and disable writes. No duplicate
reservation, spent-root refund or retry of
an uncertain committed handoff is introduced. Default-disabled physical dispatch
and the single-active ordinary Light profile stay intact.
